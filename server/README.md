# RemoteDesk Server

From `E:\AnyCraft\RemoteDesk`, run `E:\AnyCraft\.tools\dotnet\dotnet.exe run --project server/RemoteDesk.Server.csproj -- --urls http://127.0.0.1:5090` (adjust the SDK path for other machines). Local plaintext WebSocket is accepted only from loopback. Production connections must use HTTPS/WSS, with a trusted certificate configured through ASP.NET Core Kestrel standard configuration, or a TLS reverse proxy that forwards scheme securely. Never expose the loopback development listener as a public proxy without TLS.

`RemoteDesk:RegistryPath` configures the persistent public-key fingerprint to device-ID JSON registry; default `data/devices.json`. Back up this file to preserve IDs. No private keys are stored by the server. Challenge signatures use RSA-PSS SHA-256, minimum 2048-bit key, over 32 random nonce bytes. IDs are public routing identifiers, not credentials.

Messages use the camelCase `Envelope` contract in `shared/Protocol.cs`. Pending sessions expire after 45 seconds; peers must send heartbeat (or another message) within 60 seconds. Only the destination can grant a subset of requested view/control/files permissions. Sessions end when a participant disconnects. Frames go from host to viewer, input in the reverse direction, file messages both ways with file permission. Client file handling must additionally require destination consent, validate filenames and offsets, and verify hashes before committing files.

Production/LAN deployments use the independent `relay/RemoteDesk.Relay.csproj`. Configure `RemoteDesk:RelayUrl` as its public WSS endpoint, `RemoteDesk:RelayApiUrl` as its private administration base URL, and `RemoteDesk:RelaySecret` as a shared secret of at least 32 characters. Windows environment variables use double underscores, for example `RemoteDesk__RelaySecret`. Do not commit production secrets.

After consent the server creates role-specific random 32-byte tickets. `started` includes `relayUrl`, `relayTicket` and `isHost`. Each client connects to that URL and sends `attach` with `sessionId` and ticket in `payload`. Tickets expire after 45 seconds and are single-use. Media is accepted only through that relay when configured. The signaling socket continues heartbeats and end/reject messages. Session end revokes relay sockets through the private API. Authorization leases expire in 60 seconds and are renewed every 15 seconds; server failure therefore cannot leave an indefinite relay session. Remote plaintext is rejected; loopback HTTP is allowed for private API/development. Trusted proxy addresses can be configured through `RemoteDesk:KnownProxies`.

Without relay configuration, the integrated signaling transport remains available for local integration tests. This implementation does not use direct ICE/WebRTC/TURN. TLS encrypts both hops; relay operators can see session content. End-to-end encryption and hardened deployment controls remain future work. Rate limits apply per authenticated connection; public production deployments should also configure ingress connection/IP limits and request timeouts.

Integration: run the server on loopback port 5090, then `dotnet run --project tests/server/RemoteDesk.ServerTests.csproj`. These tests authenticate two real WebSocket clients and check consent, denied control, frame/file relay, rejection, ending and identity persistence. They do not test two physical Windows machines or real input/capture.

Separate relay integration: start relay on port 5091 and signaling on 5092 with the shared secret and relay URL/API configuration, then `dotnet run --project tests/relay/RemoteDesk.RelayTests.csproj`. Two authenticated clients exercise role tickets, single use, media validation, private API authorization, and signaling-driven revocation.

Add `-- --lease` after the signaling and private API URL arguments to exercise real lease timers (about 140 seconds). Set the test process `RemoteDesk__RelaySecret` to match the local relay. The test keeps an authorized session alive beyond 60 seconds through server renewals, then creates an orphan media session and verifies lease expiry despite active endpoint heartbeats. Use local test infrastructure for this administration test.
